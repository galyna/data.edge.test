# **Lovable Prompt: Data Edge Platform — Агрегация и аналитика**

## **Концепция продукта**

Интерактивный аналитический терминал, который **агрегирует данные из множественных источников** (API букмекеров, статистических сервисов) и показывает аналитику для поиска неэффективности рынка. Это не сайт с прогнозами, а инструмент для анализа данных.

**Философия:** Не «дай прогноз» → **помоги игроку найти неэффективность рынка** через агрегацию данных и аналитику.

**Core Layer:** Live odds из multiple APIs + normalizer + line-movement engine → **Analytics layer**

---

## **Технический стек**

- Frontend: Next.js 14+ (App Router), React, TypeScript
- Стилизация: Tailwind CSS (тёмная тема)
- Графики: Recharts или Chart.js
- Backend (симуляция в MVP): Node.js API routes для агрегации mock данных

- Архитектура: SSR для SEO, основной UI — клиентский SPA

## **Структура интерфейса (главный экран)**

### **Верхняя панель (Header)**
- Слева: логотип/название "Data Edge" (текст, не иконка)
- По центру: активные лиги (кнопки-фильтры: Football, NBA, MLB, etc.) — активная зелёная подсветка
- Справа: 
  - Статус источников данных: `🟢 3/5 Sources Live` 
  - Время последнего обновления: `Last sync: 5s ago`

### **Основная область (Grid Layout, 4–5 колонок):**

#### **Секция 1: Multi-Source Odds Comparison** (3 колонки)
- Таблица агрегированных данных:
  - **Матч** | **Aggregated Odds** | **Spread** | **Best Source** | **Value %**
  - Пример строки:
    ```
    Arsenal vs Chelsea | 2.15 / 3.40 / 3.20 | ±0.08 | Source B | +12.3%
    ```
  - **Aggregated Odds** = медиана/среднее из всех источников
  - **Spread** = разброс между мин/макс (зелёный = низкий spread, красный = высокий = возможная неэффективность)
  - **Best Source** = источник с лучшим коэффициентом для данного исхода
  - **Value %** = расчёт на основе aggregated vs model probability (зелёный акцент)
- Автообновление каждые 5–10 секунд

#### **Секция 2: Line Movement Graph (Multi-Source)** (2 колонки)
- График движения линии за последние 6 часов из разных источников
- Несколько линий разных цветов (тонкие, неяркие) + **жирная зелёная линия = агрегированная медиана**
- Зелёная горизонтальная полоса = value диапазон
- Интерактив: ховер показывает все источники + время + значение
- Легенда: показывает все источники (Source A, Source B, Source C...)

#### **Секция 3: Value Radar (на основе агрегации)** (1 колонка, вертикально)
- Карточка: "Value Signals from Aggregation"
- Список матчей с высоким value, обнаруженным через сравнение источников:
  ```
  🟢 Arsenal vs Chelsea
     Avg: 2.15 | Best: 2.25 | Edge: +4.7%
     Sources: 5 | Spread: Low
  ```
- Метрики:
  - **Avg** = средний коэффициент из всех источников
  - **Best** = лучший доступный коэффициент
  - **Edge** = разница между best и avg (value в процентах)
  - **Sources** = количество активных источников
  - **Spread** = качество агрегации (Low/Medium/High)

#### **Секция 4: Source Status & Anomalies** (1 колонка)
- Карточка 1: "Data Sources"
  - Список источников с индикаторами:
    ```
    🟢 Source A (BetAPI) | Latency: 120ms | Last: 3s ago
    🟢 Source B (StatsPro) | Latency: 95ms | Last: 4s ago
    🟡 Source C (OddsFeed) | Latency: 450ms | Last: 12s ago
    ```
- Карточка 2: "Aggregation Anomalies"
  - Лента аномалий, обнаруженных при агрегации:
    ```
    [Football] Arsenal vs Chelsea
    Source C deviates +0.15 from aggregate
    Possible inefficiency detected 🟢
    ```

## **Функциональность MVP**

### **Data Aggregation Engine (симуляция):**
- Mock API симулирует 3–5 разных источников данных
- Каждый источник:
  - Разные коэффициенты (реалистичный разброс ±0.05–0.15)
  - Разная задержка обновления (3–15 секунд)
  - Разная структура данных (симулируется нормализация)
- **Normalizer** унифицирует данные в единый формат:
  ```typescript
  {
    source: "Source A",
    odds: { home: 2.15, draw: 3.40, away: 3.20 },
    timestamp: "2024-01-15T14:32:00Z",
    latency: 120
  }
  ```

### **Analytics на основе агрегации:**
- **Aggregated Odds** = медиана всех источников (устойчива к выбросам)
- **Spread Calculation** = (max - min) / avg * 100 (процент разброса)
- **Value Detection**:
  - Сравнение агрегированной медианы с model probability
  - Выявление источников с аномальными коэффициентами
  - Расчёт edge = (best_odds - avg_odds) / avg_odds * 100
- **Line Movement Tracking** = агрегированная линия + отдельные линии источников

### **Интерактивность:**
- Фильтры по лигам (кнопки в header)
- Клик на матч → детальная панель с:
  - Детальное сравнение всех источников (таблица)
  - График spread во времени
  - История агрегации и аномалий
  - Метрики качества данных (latency, freshness по каждому источнику)

### **Автообновление:**
- Все источники обновляются независимо (разные интервалы)
- Агрегированные данные пересчитываются при каждом обновлении любого источника
- Визуальная индикация:
  - Краткая анимация fade на обновлённых ячейках
  - Счетчик активных источников в header
  - Таймер "Last sync: Xs ago"

## **Детали реализации**

### **Компоненты:**
1. `DataAggregator.tsx` — логика агрегации (медиана, spread, best source)
2. `MultiSourceOddsTable.tsx` — таблица с агрегированными данными
3. `LineMovementChart.tsx` — график с множественными источниками + агрегированная линия
4. `ValueRadar.tsx` — список value signals на основе агрегации
5. `SourceStatus.tsx` — статус и метрики источников

### **Стили:**
- Tailwind классы для тёмной темы
- Зелёные акценты через `text-[#00ff88]`, `bg-[#00ff88]/10`
- Графики: тёмный фон, множественные тонкие линии (серые), агрегированная линия (жирная зелёная), серая сетка

- Плавное обновление данных (fade-in на новых значениях)
- Пульсация индикаторов источников при обновлении
- Нет лишних переходов — только функциональные

## **Что НЕ включать:**
- ❌ Экспертные прогнозы или комментарии
- ❌ Реклама или баннеры
- ❌ Большие блоки текста
- ❌ Скруглённые углы (квадратный дизайн)
- ❌ Яркие декоративные цвета (только функциональный зелёный)
- ❌ Показ данных только из одного источника без агрегации

---

## **Критерии успеха прототипа:**
1. Видно агрегацию из множественных источников
2. Аналитика строится на сравнении источников (spread, best source, edge)
3. Выглядит как аналитический терминал, а не сайт букмекера
4. Зелёный используется функционально (сигналы данных, value)
5. Максимум данных, минимум текста
6. Live-обновления работают плавно
7. Понятны метрики качества агрегации (latency, freshness, spread)
